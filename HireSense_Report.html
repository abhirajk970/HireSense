Section 01
Executive Overview

HireSense is a full-stack, AI-driven talent acquisition platform engineered to modernize and automate the complete recruitment lifecycle. Built on a microservices architecture using the MERN stack (MongoDB, Express.js, React.js, Node.js) with a dedicated Python-based AI service layer, the platform combines machine learning-powered resume screening, AI-proctored online assessments, and a locally-hosted LLM (Large Language Model) that autonomously conducts structured technical interviews — all within a unified system accessible to candidates, companies, and interviewers through dedicated role-based dashboards.

🎯 Core Design Philosophy HireSense is not a chatbot layered on a job board. It is a structured evaluation engine with AI assistance — AI is deliberately constrained within a deterministic framework, ensuring reproducible, fair, and hallucination-resistant results at every stage of the hiring process.
🎯 Platform Goal

Eliminate manual bottlenecks across the entire recruitment pipeline — from the first resume submission to the final offer letter — with minimal human intervention at each stage.

💡 Key Innovation

Using a locally-hosted LLaMA 3 model via Ollama removes API costs entirely, keeps candidate data on-premises, and makes the AI system deployable without any external dependencies.

Problem Statement

Traditional hiring processes are slow, expensive, and inconsistent. HireSense directly addresses five core industry pain points:

Problem Impact HireSense Solution
Manual resume screening Slow, biased, inconsistent across recruiters ML-based auto-parsing with TF-IDF scoring
Assessment integrity Candidates cheat; results are unreliable Computer vision proctoring, time-boxed sessions
Interview scalability Senior engineers blocked as interviewers Autonomous AI interviews with LLaMA 3
Inconsistent evaluation Same candidate rated differently by different interviewers Standardized state-machine-driven scoring
AI API cost Prohibitively expensive at scale with GPT-4 etc. Locally-hosted LLM — zero per-request cost

Key Features at a Glance

🤖 AI DSA Interview

LLaMA 3-powered structured technical interviews with state machine control, progressive hints, and deterministic code scoring.

🛡️ Proctored OA

Computer vision-based monitoring, time-windowed access, auto-MCQ generation from job descriptions.

📄 Resume ML Engine

Auto-parses PDFs using spaCy NER and TF-IDF cosine similarity to score and rank applicants.

🏢 Dual Portals

Separate dashboards for candidates and companies with pipeline management, notifications, and analytics.

📅 Smart Scheduling

Cron-based automated email reminders at 2-hour and 5-minute intervals before interviews.

🔐 Sandboxed Code

Piston API executes candidate code in isolated containers against real test cases — no LLM judgment.

Microservices Breakdown

Core API Backend (backend/ · :5000)

The central server exposing 7 route modules: authentication, jobs, applications, profiles, interviews, interviewer feedback, and notifications. Handles all business logic, JWT validation, file uploads via Multer, and triggers the AI service for resume processing. Includes a cron scheduler for automated interview reminders.

OA Backend (oa-backend/ · :4000)

Dedicated online assessment service managing the question bank (seeded DSA and MCQ questions), candidate session lifecycle, proctoring event logs, time-window enforcement, and score computation upon submission.

AI Service (ai-service/ · :8000)

Python FastAPI service with two endpoints: /parse-resume uses pdfplumber, spaCy NER, and TF-IDF cosine similarity to score resumes against job descriptions; /transcribe uses the local Whisper tiny.en model to convert candidate voice input to text with zero API cost.

AI Interview Backend

Orchestrates the LLaMA 3-powered DSA interview state machine. Communicates with Ollama for LLM inference, delegates code execution to Piston API, maintains conversation memory across requests, and produces structured multi-dimension evaluation reports.

Section 03
AI Interview Engine — Design & Evaluation

The AI interview engine is the platform's most technically sophisticated component. It uses LLaMA 3 (via Ollama) wrapped inside a finite-state machine — a deliberate design that prevents the non-deterministic, open-ended behaviour of raw LLM conversations and guarantees reproducible, auditable interview sessions.

Why a State Machine? A raw LLM conversation has no guaranteed structure — the model can skip evaluation steps, be manipulated by clever candidates, or produce inconsistent results. The state machine ensures the backend, not the LLM, controls interview progression. The LLM is consulted only for subjective judgment within tightly scoped prompts.

Interview State Machine Flow

1
INIT → QUESTION_GIVEN

A DSA question is fetched from the database based on role and difficulty. The LLM optionally rephrases it in natural, conversational language before presenting it to the candidate.

2
INTUITION_EXPLAINED → INTUITION_APPROVED / HINT_TRIGGERED

The candidate explains their approach verbally. The LLM classifies the explanation as correct, partially correct, or incorrect. If correct, the interview advances to coding. If not, the progressive hint system is activated. Each hint request incurs a scoring penalty.

3
CODE_WRITTEN → CODE_EVALUATED

The candidate writes their solution in the Monaco Editor. The submitted code is sent to the Piston API, which executes it in a sandboxed container against predefined test cases. Results are fully deterministic — the LLM is not involved in code correctness judgment at any point.

4
CODE_EXPLAINED → FOLLOW_UP

The LLM, now aware of the candidate's code and test results, asks the candidate to explain time complexity, space complexity, and edge cases. Dynamic follow-up questions are then generated based on the specific solution submitted.

5
FINAL_FEEDBACK

A structured evaluation report is generated containing scores across all dimensions and narrative feedback. This report is stored and made available to both the candidate and the hiring company immediately after the session ends.

Scoring Framework

A hybrid model combining deterministic and AI-assisted evaluation. Objective code scoring carries the highest weight to prevent manipulation through good verbal communication alone.

Code Correctness (Deterministic)70%
Intuition Quality (LLM)15%
Code Explanation (LLM)10%
Communication (LLM)5%
Hint Penalty Applied to Final Score 0 hints → no deduction  ·  1 hint → −5%
2 hints → −10%  ·  3 hints → −20%

Progressive Hint System

Hints are dispensed in four progressively stronger levels. The LLM is prompted to give each level with a strict constraint — it must never reveal the full solution.

Level 1 — Directional

"Think about reducing repeated work in your current approach."

Level 2 — Structural

"Can a data structure that provides O(1) lookups help here?"

Level 3 — Strong

"Try storing elements you've seen and checking for their complements."

Level 4 — Near-Solution

"For each element, check if target minus the current value exists in your map."

Resume Screening Engine

The FastAPI AI service processes uploaded resume PDFs through a pipeline: pdfplumber extracts text → spaCy NER identifies organisations and locations → regex patterns extract CGPA, experience, and skills → TF-IDF cosine similarity computes semantic match score (0–100%) against the job description. All scores are stored with the application record.

Section 05
Setup, Roadmap & Future Scope

Prerequisites

  • Node.js v18+ — for all backend services and frontend builds
  • Python 3.9+ — for the FastAPI AI service
  • Ollama — to pull and serve LLaMA 3 locally on CPU
  • MongoDB — local instance or MongoDB Atlas cloud cluster
  • Docker (optional) — enhanced sandboxed code execution

Installation

# Clone repository git clone https://github.com/abhirajk970/HireSense.git cd HireSense # Install Node dependencies (each service) cd backend && npm install cd ../oa-backend && npm install # Set up Python AI service cd ../ai-service python -m venv venv venv\Scripts\activate pip install -r requirements.txt # Pull LLaMA 3 model (runs locally) ollama pull llama3

Environment Variables

# backend/.env MONGO_URI=mongodb://localhost:27017/hiresense JWT_SECRET=your_jwt_secret_key PORT=5000 # oa-backend/.env MONGO_URI=mongodb://localhost:27017/hiresense_oa PORT=4000

Starting Services

# Terminal 1 — Core API cd backend && npm run dev # Terminal 2 — OA Backend cd oa-backend && npm run dev # Terminal 3 — AI Service (Python) cd ai-service && uvicorn main:app --reload --port 8000 # Terminal 4 — Main Frontend cd frontend && npm run dev # Terminal 5 — LLM Runtime ollama serve

4-Week Implementation Roadmap

Week 1 — Foundation
  • MERN project structure and monorepo setup
  • JWT authentication and role-based access
  • Job posting and browsing interface
  • DSA question bank seeding scripts
Week 2 — Code Engine
  • Monaco Editor integration in interview UI
  • Piston API connection for code execution
  • Test case framework and result display
  • Application pipeline management
Week 3 — AI Integration
  • LLaMA 3 integration through Ollama
  • Interview state machine implementation
  • Intuition evaluation and hint generation
  • FastAPI resume parsing service
Week 4 — Polish & Completion
  • Full scoring engine and report generation
  • OA proctoring module integration
  • Cron-based email reminder system
  • UI polish across all dashboards

Future Scope

  • Plagiarism Detection — code similarity analysis against public solutions
  • RAG-Based Questions — personalized interview questions from the candidate's own resume
  • System Design Module — extending AI interviews beyond DSA
  • Voice-First Mode — fully spoken interviews using Whisper STT + TTS engine
  • Multi-Language Support — Java, C++, Go, Rust in the code runner
  • Analytics Dashboard — funnel metrics, time-to-hire, AI accuracy tracking
📖 Conclusion HireSense demonstrates that AI is most powerful not when used as a free-form chatbot, but when constrained inside a well-engineered system that uses it precisely for what it excels at — language understanding and contextual evaluation — while delegating objective, high-stakes decisions like code correctness to deterministic tools. The local-first LLM approach eliminates per-request API costs, keeps candidate data private, and makes the platform genuinely deployable at scale.
